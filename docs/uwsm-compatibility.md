# Compatibility with uwsm

wsmr ports the core of uwsm, but it is not a drop-in replacement for every
uwsm feature.

## Shared behavior

wsmr implements:

- `start`, `stop`, `finalize`, and `app`;
- `check is-active` and `check may-start`; and
- the internal helpers required by the generated unit graph.

The static units generated by wsmr match the units shipped by uwsm 0.26.7.
This is checked by `tests/uwsm_unit_compat.rs`.

## Deliberately omitted

wsmr does not include uwsm's compositor selector. A display manager or login
script chooses the compositor. Shell plugins, `fumon`, and `ttyautolock` are
also outside the current scope.

## Deployment difference

uwsm installs most of its unit graph as package data. wsmr embeds the unit
templates in the binary and generates the complete graph at runtime.

Both tools use the same systemd unit names. That allows a machine to offer
separate uwsm-managed and wsmr-managed display-manager entries.

## File ownership

wsmr records fingerprints for files it writes.

- A matching wsmr-owned file may be updated.
- A foreign or edited static unit causes generation to stop.
- A foreign per-compositor or tweak drop-in may be reclaimed only after wsmr
  has confirmed that no session is active.
- `stop --remove` removes only verified wsmr-owned drop-ins.
- Static graph units are never removed automatically because byte-identical
  content cannot prove whether uwsm or wsmr installed them.

## CLI differences

Known differences from uwsm are:

- no `select` command;
- no short `-v` flag at the top level;
- no automatic cleanup of the other unit rung on every start;
- the generated `wayland-wm@.service` timeout does not follow
  `UWSM_WAIT_VARNAMES_TIMEOUT`; and
- some internal `aux exec` and `aux readiness` options are more permissive.

wsmr also accepts `runtime` as an alias for uwsm's canonical `run` unit rung.

## Readiness watcher

Upstream uwsm double-forks its watcher. wsmr starts a new process instead.
Forking after zbus initialized its reactor left the child with a broken D-Bus
connection; spawning gives the watcher a clean process and connection. The
Tier B integration test exposed this difference.

No golden snapshot currently protects the complete CLI shape. Adding one is
tracked in [Open work](todo.md).
